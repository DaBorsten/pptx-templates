# Fork notes

This repository is a fork of
[singerla/pptx-automizer](https://github.com/singerla/pptx-automizer). It
only **adds** features. Nothing upstream is changed in behavior, so the fork
can follow upstream with a plain merge.

The fork is published as **pptx-templates**
([DaBorsten/pptx-templates](https://github.com/DaBorsten/pptx-templates)).
Upstream keeps the name `pptx-automizer`. Code, docs and tests use the new
name everywhere, except links to upstream issues and pull requests, so a merge
from upstream can conflict on those lines. After such a merge, replace
`pptx-automizer` with `pptx-templates` in the conflicting lines.

## Updating from upstream

```bash
bash tools/fork/sync-upstream.sh        # merges upstream/main into main
```

The script fetches `upstream`, merges, regenerates `AI-INSTRUCTOR.md`
(generated file, never resolved by hand), then runs `tsc` and `yarn test`. It
does not push. With `rerere` enabled, a conflict you resolved once is
resolved automatically the next time.

## Rules for fork extensions

1. **Code lives in `src/extensions/<feature>/`**, including its own types. Use
   upstream internals (`XmlHelper`, `MultiTextHelper`, …) by importing them,
   never by editing them. If upstream renames something, `tsc` and the tests
   tell you, and the merge itself still goes through cleanly.
2. **Public API is wired in one place**: `src/extensions/index.ts`. Add new
   `modify.*` helpers to `extensionModifiers` and export new things from
   there. `src/index.ts` already pulls in both. Don't add more lines there.
3. **Tests**: new files `__tests__/<feature>.test.ts`, reusing the templates
   in `__tests__/pptx-templates/`.
4. **Docs**: a new page `docs/<feature>.md`, registered with one line each in
   `website/sidebars.ts` and `tools/ai-instructor/template.md`. Then run
   `yarn docs:ai`. Don't edit upstream docs pages.
5. **Changelog**: in `CHANGELOG.md` under `## [Unreleased]`.

### Lines the fork adds to upstream files

These are the only places where an upstream merge can conflict. Each one is
an added line, and no upstream line is changed:

| File | Added |
|---|---|
| `src/index.ts` | 3 lines at the very top (`import { extensionModifiers } …`, `export * from './extensions'`), 1 line at the start of `export const modify = {` (`...extensionModifiers,`) |
| `website/sidebars.ts` | `'template-logic',` before `'generation'` |
| `tools/ai-instructor/template.md` | `<!-- include: docs/template-logic.md -->` after the text include |
| `AGENTS.md` | 1 line pointing agents to this file |
| `AI-INSTRUCTOR.md` | generated, regenerated by the sync script |

### Upstream lines the fork changes (dependency updates)

The fork runs newer dependencies than upstream (pptxgenjs 4, TypeScript 6,
ESLint 10). These lines are changed, not only added, and may conflict on a
merge:

| File | Change | Why |
|---|---|---|
| `package.json` | dependency ranges; `test`, `test-coverage`, `test:visual` run `node --experimental-vm-modules node_modules/jest/bin/jest.js` | pptxgenjs 4 loads `node:fs`/`node:https` via `import()`, which Jest only allows with that flag |
| `src/helper/generate/generate-pptxgenjs.ts` | 1 import + `repairSvgFallbacks(...)` around `this.generator.stream()` | pptxgenjs 4 writes SVG bytes into the PNG fallback, see `src/extensions/pptxgenjs-compat/` |
| `tsconfig.json` | `strict: false` explicit, `moduleResolution: bundler`, `rootDir: src`, `lib: es2022`, `baseUrl` removed | TypeScript 6 defaults (`strict` on, `rootDir`) and deprecations (`node10`, `baseUrl`); `es2022` for `Error` `cause` |
| `src/classes/has-shapes.ts`, `src/classes/template.ts`, `src/helper/xml-slide-helper.ts`, `src/helper/xml-template-helper.ts` | rethrown errors pass `{ cause: error }` | ESLint 10 `preserve-caught-error` |
| `src/helper/archive/archive-jszip.ts` | `let xmlString: string;` without the unused `''` | ESLint 10 `no-useless-assignment` |
| `AGENTS.md` | single-test command `yarn test <file>` | plain `npx jest` lacks the flag |
| `.github/workflows/ci.yml` | `26.x` added to the test matrix | the fork supports Node 20 through 26 |
| `CHANGELOG.md`, `ROADMAP.md` | replaced: the changelog starts at 0.1.0, the roadmap is empty | the fork has its own versions; `sync-upstream.sh` keeps the fork's copies on a conflict |

If upstream ever ships a helper with the same name as a fork helper,
upstream's version wins (it comes later in the `modify` object). The tests
of the fork extension then show it.

## Releasing

`.github/workflows/release.yml` (fork-only file) publishes to npm with
trusted publishing (OIDC), no token. Bump `version` in `package.json` on
`main`, then push a single tag: `git tag v0.1.1 && git push origin v0.1.1`.
The workflow refuses tags whose commit is not on `main` or whose name does
not match `package.json`. Upstream tags are not fetched (`sync-upstream.sh`
sets `tagOpt --no-tags`), because v0.1.0–v0.9.3 would collide with the
fork's versions; the copies forked in were deleted on 2026-11-03.
